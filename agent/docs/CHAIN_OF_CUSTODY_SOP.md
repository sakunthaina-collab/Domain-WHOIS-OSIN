## 1. หลักการและวัตถุประสงค์ (Principles & Purpose)

ภายใต้มาตรฐาน **ISO/IEC 27037:2012** และกฎหมายวิธีพิจารณาความอาญา (ทั้งเขตอำนาจศาลไทยและไต้หวัน) พยานหลักฐานดิจิทัลจะมีน้ำหนักรับฟังได้ในชั้นศาลก็ต่อเมื่อสามารถพิสูจน์ **สายการครอบครองอย่างต่อเนื่อง (Unbroken Chain of Custody)** ได้ว่า:
1. **ใคร (Who):** เป็นผู้เก็บรวบรวม วิเคราะห์ ตรวจสอบ และเก็บรักษาในทุกช่วงเวลา
2. **เมื่อใด (When):** วันและเวลาที่รวบรวม (แสดงทั้ง UTC, เวลาไทย UTC+7, และเวลาไต้หวัน UTC+8)
3. **ทำอะไรและอย่างไร (What & How):** ใช้เครื่องมือใด พารามิเตอร์ใด (`00_run_manifest.json`) และปฏิบัติตามหลัก Passive Reconnaissance (`passive_only=True`)
4. **ความเหมือนเดิมของหลักฐาน (Cryptographic Identity):** ค่า SHA-256 รายไฟล์, Merkle Root (`artifact_manifest.json`), และ Audit Head Hash (`anchor_ledger.json`) ณ เวลาส่งศาล ตรงกับวินาทีที่เก็บรวบรวม 100%

## 2. บทบาทและการแบ่งแยกหน้าที่ (Roles & Segregation of Duties — SoD)

เพื่อป้องกันผลประโยชน์ทับซ้อนและการแก้ไขหลักฐานโดยพลการ ห้ามมิให้บุคคลคนเดียวถือครองทุกบทบาทในคดีเดียวกัน โดยแบ่งแยกหน้าที่เป็น 4 บทบาทดังนี้:

| บทบาท (Role) | หน้าที่ความรับผิดชอบหลัก | สิทธิ์ในระบบ (Access Rights) | ข้อห้าม (SoD Constraints) |
|---|---|---|---|
| **1. เจ้าของสำนวนคดี (Case Owner / Lead Investigator)** | กำหนดขอบเขตการสืบสวน อนุมัติหมายเลขคดี (`<CASE_ID>`) และอนุมัติการรันสกิลความเสี่ยงสูง (`_confirmed=True`) | อ่านรายงานสรุปและลงนามอนุมัติคำสั่ง | ห้ามแก้ไขไฟล์ใน `artifacts/` หรือ `logs/` |
| **2. นักวิเคราะห์ (Forensic Analyst / Operator)** | สั่งรันระบบ `main.py` เพื่อรวบรวมข้อมูล OSINT และสร้างสำนวนคดี 2 ภาษา (`th` / `zh-TW`) | รันคำสั่งผ่าน CLI ภายใต้ Guardrails | ห้ามลบหรือแก้ไข Audit Log / Anchor Ledger หลังรันเสร็จ |
| **3. ผู้ควบคุมหลักฐาน (Evidence Custodian)** | ตรวจสอบความสมบูรณ์หลังจบเคส นำเข้าพื้นที่จัดเก็บปลอดภัย (WORM / Vault) และควบคุมการเบิก-จ่ายสำเนา | รัน `verify_all.py`, จัดการพื้นที่เก็บรักษา และถือครองกุญแจลงนาม (GPG/Vault) | ห้ามเป็นผู้สั่งรันสืบสวนในคดีที่ตนเป็นผู้เก็บรักษา |
| **4. ผู้ตรวจสอบอิสระ (Independent Reviewer / Auditor)** | ตรวจสอบความสมบูรณ์ของทั้ง 5 เสาหลักตาม `docs/AUDITOR_GUIDE.md` ก่อนส่งมอบให้พนักงานสอบสวนหรือศาล | สิทธิ์อ่านอย่างเดียว (Read-Only) | ต้องไม่เป็นบุคคลเดียวกับ Forensic Analyst ที่รันเคสนั้น |

## 3. ขั้นตอนการรวบรวมและผนึกพยานหลักฐาน (Acquisition & Cryptographic Sealing)

ทุกครั้งที่มีการปฏิบัติการสืบสวนในคดีใหม่ นักวิเคราะห์และผู้ควบคุมหลักฐานต้องดำเนินการตาม 4 ขั้นตอนบังคับนี้:

### ขั้นที่ 1: การรันและบันทึกพารามิเตอร์อัตโนมัติ (Automated Acquisition)
```bash
python main.py --profile investigator --case-id <CASE_ID> --task "<คำสั่งสืบสวน>"
```
ระบบจะสร้างหลักฐานทางเทคนิคอัตโนมัติ 4 ส่วน:
1. `artifacts/<CASE_ID>/00_run_manifest.json` — บันทึกสภาพแวดล้อม รุ่นโมเดล Seed และ Registry Hash
2. `artifacts/<CASE_ID>/001_*.json` .. `00N_*.md` — ไฟล์ผลลัพธ์การสืบสวนและสำนวนคดีสองภาษา
3. `artifacts/<CASE_ID>/audit.jsonl` และ `logs/audit.jsonl` — บันทึก Hash Chain แบบคู่ขนาน (Dual Chain)
4. `artifacts/<CASE_ID>/artifact_manifest.json` — คำนวณ SHA-256 รายไฟล์และ Merkle Root รวมทั้งสำนวน

### ขั้นที่ 2: การตรึงหมุดภายนอก (External Anchoring)
ทันทีที่จบการทำงาน ระบบจะบันทึกค่า `head_hash` และ `entry_count` ลงใน `logs/anchor_ledger.json` และสร้าง Git Tag:
```text
anchor/<CASE_ID>/<HEAD_HASH_12_CHARS>
```

### ขั้นที่ 3: การตรวจสอบรับรองก่อนผนึกซองดิจิทัล (Pre-Sealing Verification)
ผู้ควบคุมหลักฐาน (Custodian) รันคำสั่งตรวจสอบต่อหน้านักวิเคราะห์:
```bash
python scripts/verify_audit.py logs/audit.jsonl <CASE_ID> logs/anchor_ledger.json
python scripts/verify_audit.py artifacts/<CASE_ID>/audit.jsonl
python main.py --verify-artifacts <CASE_ID>
```
เมื่อทั้ง 3 คำสั่งคืนค่า Exit Code `0` จึงบันทึกค่า **Merkle Root** และ **Audit Head Hash** ลงใน **แบบฟอร์ม CoC-01 (§7.1)**

### ขั้นที่ 4: การจัดเก็บเข้าคลังหลักฐาน (Archival & WORM Locking)
นำสำเนาโฟลเดอร์ `artifacts/<CASE_ID>/` พร้อมไฟล์ `logs/anchor_ledger.json` บีบอัดเป็นไฟล์ `.zip` หรือ `.tar.gz` คำนวณค่า SHA-256 ของไฟล์บีบอัด แล้วจัดเก็บในสื่อบันทึกแบบเขียนครั้งเดียว (WORM Storage / S3 Object Lock / Optical Media)

## 4. มาตรฐานการจัดเก็บและการควบคุมการเข้าถึง (Storage & Access Control)

1. **การเข้ารหัสข้อมูลขณะจัดเก็บ (Encryption at Rest):** พื้นที่จัดเก็บสำนวนคดีต้องเปิดใช้งาน BitLocker (Windows), LUKS (Linux), หรือ FileVault (macOS) ด้วยมาตรฐาน AES-256
2. **การป้องกันการเขียนทับ (Immutability):** โฟลเดอร์คดีที่ปิดการรวบรวมแล้วต้องตั้งค่าเป็น Read-Only และสำรองขึ้นระบบที่เปิดใช้งาน Object Lock (Compliance Mode)
3. **การรักษาความแม่นยำสองภาษา (Bilingual Preservation):** ห้ามแปลงรหัสอักขระ (Encoding) ของไฟล์รายงาน ต้องคงรูปแบบ **UTF-8** เสมอ เพื่อรักษาอักษรจีนดั้งเดิม (Traditional Chinese เช่น `新北市中和區自立路147–149號 / 秀山郵局`) และชื่อแฝง (`予安`, `箏箏`, `小白`) ไม่ให้เพี้ยนเป็นอักขระขยะ (Mojibake)

## 5. นโยบายระยะเวลาเก็บรักษาและการทำลาย (Retention & Disposal Policy)

| ประเภทคดี / ข้อมูล | ระยะเวลาเก็บรักษาขั้นต่ำ | อ้างอิงข้อกฎหมาย | เงื่อนไขการทำลายหลังครบกำหนด |
|---|---|---|---|
| **คดีค้ามนุษย์และอาชญากรรมข้ามชาติ** | **ตลอดอายุความ (สูงสุด 20 ปี)** หรือจนกว่าคดีจะถึงที่สุด | พ.ร.บ. ป้องกันและปราบปรามการค้ามนุษย์ พ.ศ. 2551 / 臺灣人口販運防制法 | ต้องได้รับอนุมัติร่วมกันเป็นลายลักษณ์อักษรจาก Case Owner + DPO + Custodian (แบบฟอร์ม CoC-03) |
| **ข้อมูลจราจรทางคอมพิวเตอร์และ Audit Log ทั่วไป** | **ไม่น้อยกว่า 90 วัน** (และขยายได้ถึง 2 ปีตามคำสั่งพนักงานเจ้าหน้าที่) | มาตรา 26 พ.ร.บ. ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ | ลบด้วยวิธี Cryptographic Erasure / Secure Wipe (NIST SP 800-88 Purge) |
| **ข้อมูลทดสอบระบบ (Dry-Run / Smoke Tests)** | **30 วัน** | มาตรฐานการบริหารจัดการภายใน | ลบเฉพาะโฟลเดอร์ทดสอบที่ไม่ใช่คดีจริง |

## 6. ขั้นตอนการส่งมอบพยานหลักฐานให้หน่วยงานบังคับใช้กฎหมาย (External Law Enforcement Handover)

เมื่อต้องส่งมอบสำนวนคดีและพยานหลักฐานดิจิทัลให้แก่ **กรมสอบสวนคดีพิเศษ (DSI), สำนักงานตำรวจแห่งชาติ, กระทรวงการต่างประเทศ (MFA), หรือสำนักงานตรวจคนเข้าเมืองและอัยการไต้หวัน (臺灣移民署 NIA / 地檢署)**:

1. **จัดเตรียมชุดส่งมอบ (Evidence Package):**
   - โฟลเดอร์ `artifacts/<CASE_ID>/` (ประกอบด้วย `00_run_manifest.json`, ไฟล์หลักฐานทั้งหมด, `audit.jsonl`, และ `artifact_manifest.json`)
   - สำเนาไฟล์ `logs/anchor_ledger.json`
   - สำเนาคู่มือตรวจสอบ `docs/AUDITOR_GUIDE.md` และ `docs/SIGNED_HASHES.txt`
2. **การตรวจสอบร่วมกัน ณ จุดส่งมอบ (Joint Verification on Handover):**
   - ให้ผู้รับมอบ (หรือผู้เชี่ยวชาญของหน่วยงานรัฐ) รันคำสั่งตรวจสอบ SHA-256 และ Merkle Root ต่อหน้าผู้ส่งมอบ
3. **การลงนามในใบรับมอบสองภาษา (Bilingual Receipt Signing):**
   - กรอกและลงนามใน **แบบฟอร์ม CoC-02 (§7.2)** ทั้งผู้ส่งมอบ ผู้รับมอบ และพยาน โดยเก็บต้นฉบับไว้ที่ผู้ควบคุมหลักฐาน 1 ฉบับ และส่งมอบให้หน่วยงานรัฐ 1 ฉบับ
